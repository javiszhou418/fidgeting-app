# 单抽、收藏与收藏盒定制：分批原型计划

最后更新：2026-08-12

这份计划只定义可单独确认的小节点。原型必须放在独立 Preview/Tools 入口，不替换 shipping `GachaStoreView`、`PremiumDisplayCase` 或真实经济数据；用户批准某个节点后，才为该节点另建正式接入任务。

## 1. UI 修复

### Library 横向滑动方向

- 手指从屏幕右侧向左滑：当前产品表面必须向左退出，下一产品从右侧进入。
- 手指从屏幕左侧向右滑：当前产品表面必须向右退出，上一产品从左侧进入。
- 页面序号语义不变；必须用运行中的 iOS Simulator 完成一次完整左滑和右滑，并断言页面变化方向。
- 本节点不等待抽卡或收藏盒原型，可独立测试、预览和发布。

## 2. UI 修改（隔离 Demo）

### 顶层信息架构

- 两个 Tab：`抽取` 与 `收藏`。
- `抽取` Tab 隐藏概率和保底细节，只留一个低权重的“规则”二级入口。
- 单抽和十抽固定在屏幕底部；第一轮只启用单抽，十抽显示“稍后开放”。
- 所有产品级文字按钮只显示文字，不加入装饰 icon。

### 收藏 Gallery / Grid

- 同一 Grid 展示已拥有陀螺、未拥有陀螺和对应图纸进度。
- 稀有度采用四档：蓝色基础、绿色精制、紫色珍藏、金色传世。
- 图纸是明确的产品定向材料；默认 Demo 规则为同款 `10/10` 图纸可打造对应陀螺。
- `收藏` Tab 同时提供“背包”和“兑换/打造”状态，不把抽取概率混入 Gallery。

### 货币语义

- 抽取券是单抽/十抽的唯一抽取消耗；Demo 不允许齿轮币替代抽取券。
- 齿轮币暂定为打造手续费与收藏盒外观定制货币，不提供物理、成长或概率加成。
- 进入抽卡页不得连接 App Store。只有用户主动点击齿轮币充值入口后，才允许打开充值页并开始请求 StoreKit 商品。
- Demo 使用本地假数据，不调用 StoreKit、不扣真实余额、不发送 Unity 抽取消息。

## 3. 全新功能开发（先做原型，暂不接正式链）

### 收藏盒配色

- 可定制区域拆为三组：四枚角柱/螺丝、外层透明塑料盒、中央背景/内槽。
- 首轮提供与四档稀有度对应的蓝、绿、紫、金 preset；每组颜色仍可在后续单独细调。
- 配色只改变材质和灯光表现，不改盒体尺寸、相机、奖品姿态、碰撞或 Haptic。
- 揭晓动画可以临时使用稀有度 preset，收藏盒个人定制则作为持久化外观；两者的覆盖优先级需要在正式接入前锁定。

### 图纸打造

- 需要新增产品定向图纸库存、10 张阈值、打造费、打造结果和已拥有重复规则。
- 该系统与现有通用 duplicate shard/兑换所不是同一概念；正式实现前必须决定是迁移旧碎片，还是并行保留两种材料。

### 单抽正式链路

- 抽取券扣除、奖品决定、保底与持久化继续由 Unity 权威经济层负责。
- 原生 UI 只发起请求和播放权威结果，不在 SwiftUI 重新 roll 稀有度。
- 只有动画完成后才提交 Gallery 新增状态；中断/后台恢复必须可重入且不得重复发奖。

## 4. 动画效果（当前描述仍需用 Demo 校准）

首轮分镜固定为：

1. 当前抽取页压暗，收藏盒背面进入。
2. 收藏盒沿竖轴翻转至正面，稀有度色从角柱和内槽建立。
3. 奖品清晰可见后，收藏盒按既有层级做有限散开。
4. 盒体淡出，只保留奖品本体。
5. 一道与稀有度同色的过光扫过奖品，显示完成状态。

首轮 Demo 需要用户校准但不阻塞开工的参数：

- 翻转是 180° 机械转身，还是带轻微俯仰的产品展示转身。
- “散开”是盒体八层拆解、奖品自身零件拆解，还是两者都做。默认先做盒体散开，奖品保持完整。
- 过光是一次 0.5–0.8 秒的窄高光，还是更强的全屏闪光。默认采用窄高光，避免过曝。
- 抽到图纸时，盒内展示图纸卡还是展示目标陀螺的幽灵轮廓。默认展示图纸卡。

## 5. 独立确认节点

- A：Library 同向滑动——正式 runtime 修复 + Simulator 真手势录像。
- B：抽取/收藏双 Tab——独立 SwiftUI Demo 截图，不接正式商店。
- C：收藏盒四色定制——独立 Unity 预览，不改 shipping prefab。
- D：单抽揭晓分镜——独立短视频，不扣券、不发奖。
- E：经济规则——在 B/C/D 获批后，单独确认图纸、齿轮币与旧碎片的关系，再接正式数据链。

每个节点分别汇报、分别展示、分别批准；不再为了等待其他节点而堆成一个大版本。

## 6. 2026-08-12 shipping 差距审计

隔离 Demo 已证明信息层级和视觉方向，但不能直接复制进正式组件。正式链已有 Unity 权威概率、保底、
收据、持久化、重复碎片兑换、四档稀有度枚举和收藏 Grid 基础；这些能力必须继续作为唯一数据源，
SwiftUI 不得使用 Demo 的假目录、假拥有状态、`60/30/9/1` 占位概率或本地确定性抽取序列。

### 正式抽卡 UI

- 正式 `GachaStoreView` 当前仍把单抽/十抽放在滚动内容中部，并把抽取、充值、兑换和收藏串成一个页面；
  需要在原组件内复用现有 `GachaStoreModel` 数据，重构成“抽取 / 兑换”和“收藏”双 Tab，并把抽取操作固定到底部。
- 正式页面虽已有概率 sheet，但主页仍直接显示保底阈值和进度；概率与保底需要一起移入二级规则页。
- 第一批只开放单抽。十抽继续保留权威 Unity 能力，但正式 UI 暂时显示不可用，不删除十抽数据和收据路径。
- 当前抽取券不足时会自动改用齿轮币，且 Unity 仍接受 coin draw；这与“抽取券是唯一抽取消耗”冲突，
  必须做 Unity 经济迁移和回归测试，不能只改 Swift 文案。
- 当前进入抽卡页会立即创建 `GachaCoinShopView` 并启动 StoreKit。正式接入必须移除常驻商店，只有用户
  主动点充值后才创建 storefront、启动商品加载；verified transaction、restore 和既有余额保留。
- 蓝/绿/紫/金继续映射既有 `Standard / Refined / Signature / Heirloom` raw value，不创建第二套稀有度枚举。

### 图纸、碎片与齿轮币

- 正式 catalog 目前没有 `Blueprint` prize kind，也缺少真实陀螺和产品定向图纸条目；Gallery 只能复用
  现有 Grid 框架，内容 schema、库存、`10/10` 打造阈值和打造结果都需要新增 Unity 权威实现。
- 正式链已有“重复物转合金屑并兑换”的余额和测试。接入图纸前只剩一个产品决策：合金屑是否迁移/改名
  为蓝图碎片，还是保留“通用合金屑 + 产品定向蓝图”两套材料。
- 既有齿轮币余额不得清空。首批目标用途为打造手续费和已拥有产品的收藏盒外观定制；具体开放项目和
  定价需独立确认后接入 `CraftingService` / customization 消费 API。

### 收藏盒与单抽揭晓

- 正式收藏盒已有独立螺丝/领圈、背景/内衬、圆角内槽/边光 renderer，以及八层散开和奖品跟随；
  但需要用 prefab 显式 renderer 分组和 MaterialPropertyBlock API 接入四色 profile，不能沿用 Demo 的运行时名称匹配。
- 正式 `GachaRevealDirector` 当前只在测试中创建，Coordinator 抽取成功后只发布收据，真实单抽不会启动 3D 揭晓。
- 正式 catalog 的八个 `ContentReference` 尚无完整 presentation resolver；必须先保证 8/8 奖品都能实例化、
  正确 fit、销毁/归还，并且不触发历史 idle spin，才能做端到端揭晓。
- 正式黑色 SwiftUI 抽取 sheet 会遮住 Unity 动画。单抽接入需要专用透明 presentation session，负责相机、
  Library 产品隐藏/恢复、收据暂存、busy gate、Unity→native phase/completion；失败、中断和后台恢复不得重复扣券或发奖。
- 对外状态机严格保持六拍：背面、翻正、可读停留、盒体散开、仅奖品、过光完成。Demo 内部的
  `ExplodedHold` 只作为散开阶段内部停顿，不成为第七个产品状态。

### 批次顺序

1. 正式 UI presentation：双 Tab、规则二级页、底部单抽、十抽禁用、四色 badge；继续消费现有权威数据。
2. StoreKit 延迟加载与券-only 抽取契约；保留已购信用、恢复和既有余额。
3. 收藏盒三组显式材质绑定与四色 profile；单独生成 shipping 预览批准。
4. 严格六阶段 Director；先用现有三叶奖品生成 shipping storyboard/动画批准。
5. Catalog 八项 presentation resolver、Blueprint schema、打造/定制经济迁移。
6. 仅单抽端到端 Coordinator/native 接入；十抽路径保持关闭，最后再进行 iPhone 真机验收。

每一批单独编译、测试、预览和批准，不等待后续批次一起完成。

## 7. 2026-08-12 主推商品与同系列皮肤 Demo

- 用户确认商店首屏可用大 Banner 告知主推产品，并在下方陈列皮肤；隔离 Demo 已按此增加“主推陀螺”与
  “同系列皮肤”两个层级，可购买内容概念上拆为陀螺和皮肤两类。
- 当前正式商品目录没有陀螺/皮肤 StoreKit SKU、地区价格、entitlement、`releaseAt` 或 `isNew`，因此
  Demo 不伪造“付费新品”“最新上架日期”“立即购买”或价格，统一标为“商品演示 · 尚未开放购买”。
- 主 Banner 使用真实 `metal-three-blade`「三叶金属」，因为它同时具备 shipping 产品 ID、真实模型视觉、
  十款 runtime 皮肤和十张随包缩略图；磁吸扇牌属于 Fan 玩具，不能冒充陀螺。
- 下方使用真实三叶金属成长皮肤「镜铬极光 LV.100」「星陨黑曜 LV.90」「钛虹热变 LV.75」。这些等级
  是已有权威进度门槛，不等同于正式 rarity 或上架日期。
- Demo 的 iPhoneOS/Simulator arm64 type-check、真实 Simulator 预览和二进制隔离审计均通过；应用包不链接
  StoreKit，也不引用 Unity/Gacha bridge。证据位于 `Artifacts/SingleDrawStoreDemo/`。
- 正式接入前需要新增独立 commerce catalog，至少包含商品类型、content ID、父产品、StoreKit Product ID、
  thumbnail、acquisition kind、featured/banner、releaseAt、availability 和 entitlement type；实际价格必须读取
  App Store `displayPrice`，进入商店仍不得提前启动 StoreKit。
