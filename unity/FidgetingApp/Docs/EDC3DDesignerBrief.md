# Fidgeting App｜EDC 玩具 3D 设计与 Unity 资产需求 Brief

版本：v1.0（供首次沟通、报价与制作验收）  
目标平台：iPhone / Unity 6 / URP  
项目形态：同一个手机 App 内持续扩展的数字 EDC 玩具收藏

## 可直接发给设计师的开场

我们正在制作一款手机端数字指尖玩具 App，想确认贵方是否做过 EDC 解压玩具、推牌、磁吸滑块、棘轮拨盘或指尖陀螺一类的 3D 设计/建模。我们需要的不是普通静态产品渲染模型，而是一套可以直接进入 Unity、并可由程序驱动各个机械部件的实时 3D 资产。

参考视频里最重要的不是单纯“转起来”，而是金属连接件之间呈现出的阻尼、段落、脱档、吸附、棘轮和碰撞关系。例如其中的树脂件需要能围绕金属连接轴独立、连续地旋转。最终的速度、阻尼、段落、回弹、声音和手机触感由我们在 Unity 中控制；设计师需要在建模阶段把运动结构拆分好，正确设置转轴、滑轨、零位、装配间隙和零件层级。

希望先按下方标准评估一款首发模型的设计费、建模费、贴图费、修改轮次和周期。如有类似项目，请一并提供作品或 Unity 实时资产案例。

## 1. 项目目标

Fidgeting App 是一个数字 EDC 玩具库，目前的产品目录包含：

- 自由轮指尖陀螺；
- 有磁吸段落和棘轮感的旋转件；
- 金属三叶、镜钢四翼、石墨双叶等不同外形和材质的转子；
- 磁吸推牌/侧推滑盖；
- 后续可扩展按钮、拨盘、滑块、Snap、Pop 等机械玩法。

模型会以近距离 Hero 视角占据手机屏幕主体。外观不仅要好看，还要让玩家从零件关系中“看懂”哪里能按、能推、能转、会吸附，以及机械力量从哪里传递。

本轮首要目标是制作一款原创、可交互、移动端可运行的 EDC 模型。参考产品和视频只用于理解玩法、尺度、装配关系与材质，不做品牌、商标、专利外形或装饰图案的 1:1 复制。

## 2. 对参考玩法的理解

EDC 玩具的把玩乐趣主要来自结构和反馈的组合，而不是单一动画：

- **自由轮**：手指明确输入速度后持续旋转，再自然衰减；静止时不能自己转。
- **磁吸段落**：未超过脱档力度时保持在当前稳定点；超过阈值后移动；低速时吸回最近档位并停稳。
- **棘轮/拨盘**：跨过真实段落时产生清晰、可计数的节奏；速度越高，节奏越密。
- **推牌/滑块**：由外壳、活动盖、轨道、限位、低摩擦接触层、磁铁或弹性件共同建立开合和回吸关系。
- **复合结构**：金属骨架负责承力和定位，树脂/聚合物件可以独立旋转、推移或替换；复杂度来自合理的装配层级，不是把细节全部焊成一块。

在 App 内，真正的阻尼、磁力曲线、段落数量、回弹和触觉由 Unity 机制状态机计算。模型负责让这些状态具有可信、可读的视觉结构。

## 3. 首款模型的核心结构要求

结合当前参考视频，至少需要以下可独立控制的零件组：

1. `StaticFrame`：金属主体、固定支架或外壳，不参与主旋转。
2. `AxleOrConnector`：金属连接轴、轴套、垫片、轴承或定位结构；与真实旋转中心一致。
3. `ResinRotor`：树脂件/复合材质活动件，必须与金属件分离，支持围绕轴线连续旋转 360°。
4. `FingerCapOrHub`：若玩家捏住中心操作，则上下指帽、固定中心或轮毂应根据真实结构与转子分开，不能默认全部一起转。
5. `DetentOrMagnetParts`：如结构可见，磁铁、滚珠、弹片、齿圈或止挡应作为可识别零件；不需要真的在 Unity 中进行磁场或齿轮接触仿真。
6. `Fasteners`：必要的螺丝、定位柱、卡扣和装饰盖；重复小件可合并渲染，但需保留合理装配关系。

如果一个产品包含两个或更多可独立旋转/滑动的部件，每个运动组都必须有自己的父节点、pivot、运动轴和零位，不能合并成单一 Mesh。

## 4. 动画与 Unity 的责任边界

### 设计师需要完成

- 根据真实机械关系拆分静止件和运动件；
- 将 pivot 精确放在真实转轴、铰链或滑轨中心；
- 设定清晰、无穿插的装配零位；
- 提供运动方向、最大行程、机械限位和可见装配间隙；
- 为拆解展示保留独立零件层级；
- 冻结/应用缩放，避免负缩放和非统一缩放；
- 保持干净的命名、法线、切线和 UV；
- 如能提供一段仅用于说明机构的预览动画或转台动画，可作为沟通材料，但不是必需交付。

### Unity 侧负责

- 触摸拖动、甩动、点击、设备姿态和 Shake 输入；
- 自由轮角速度、惯性、frame-rate-independent 阻尼和停转；
- 磁吸 Breakaway、Travel、Capture、Detent 和归零状态；
- 推牌的拖动、吸附、回弹、打开/闭合和 Reset；
- 旋转、翻转、爆炸拆解和成长装配动画；
- 跨档音效、语义 Haptic、Core Motion 和 iPhone 真机调校；
- 简化碰撞体、Rigidbody 和最终 Unity Prefab/场景接线。

### 关键结论

**最终交互动画不要求设计师烘焙，但运动接口必须在建模阶段留好。** 如果只交付一个焊死的整模、pivot 在世界原点或零件坐标混乱，Unity 后期无法可靠还原真实机械动作。

## 5. 推荐层级与坐标

旋转类模型建议：

```text
EDC_Product_Root
├── StaticAssembly
│   ├── StaticFrame
│   ├── AxleOrConnector
│   └── FingerCap_Static
├── RotorDynamic                 ← 本节点由 Unity 驱动
│   ├── ResinRotor
│   ├── MetalTrim_Rotor
│   └── Counterweights
├── DetailAssembly
│   ├── Bearings
│   ├── Fasteners
│   └── OptionalDetentRing
├── MechanismMarkers
│   ├── PIVOT_Rotor
│   ├── LOC_Reset
│   └── LOC_Grip
└── Collision
    ├── COL_Static
    └── COL_Rotor
```

推牌/滑块类模型建议：

```text
EDC_Slider_Root
├── BaseAssembly
├── SliderDynamic               ← 本节点由 Unity 沿局部 +X 驱动
│   ├── TopPanel
│   └── SliderCarrier
├── GuideAndStops
├── MagnetArray
├── Fasteners
├── AXIS_Slider_Start
├── AXIS_Slider_End
└── Collision
```

项目统一约定：

- Unity 单位为米，`1 Unity unit = 1 m`；模型按真实 EDC 尺寸制作，不要用任意大比例后再缩放。
- Unity 坐标为 Y-Up。旋转类模型默认让轴承/主旋转轴沿局部 `+Y`，主体展开在 `XZ` 平面。
- 推牌默认闭合为本地零位，活动件沿局部 `+X` 打开。
- 根节点位置与旋转归零，根节点缩放为 `(1,1,1)`。
- 轴线、模型几何中心和设计质心应对齐；需要偏心的设计必须在说明文件中标注。
- 所有运动件在装配态不得互相穿插；近景下应看得到可信的层缝、轴套或垫片关系。

坐标约定如与具体设计冲突，可在 blockout 阶段讨论调整，但同一资产内必须保持一致。

## 6. 段落、齿圈和磁铁的特殊要求

App 的段落数会由程序在不同手感预设间切换，当前包括 8、12、24、36 档。因此：

- 不建议把一个固定齿数做成无法替换、又非常醒目的外露结构；否则视觉齿数会与实际段落/Haptic 不一致。
- 如果外露齿圈是核心视觉，请提供 `DetentRing_08 / 12 / 24 / 36` 四个可替换版本，或提出能避免视觉计数冲突的隐藏结构。
- 磁铁、滚珠和弹片可以作为视觉件，但不作为复杂实时碰撞体。
- 运动用碰撞体必须与高模齿形分开；Unity 不会让每颗齿或每块磁铁进行真实接触求解。

## 7. 造型与材质方向

希望整体是高端、克制、可收藏的工业 EDC 质感，强调真实材料差异：

- 喷砂/珠砂金属主体：宽而柔的高光，不能像塑料灰。
- 抛光或镜钢倒角：只在边缘形成连续亮线，不能把高光直接画入 Base Color。
- 拉丝金属：纹理方向要与加工逻辑一致，旋转时不能出现明显摩尔纹和闪烁。
- 树脂/聚合物：与金属在粗糙度、透光感、边缘厚度和色彩深度上有明确区分。
- 黑色 POM、垫片、轴承和连接环：通过材质和层缝建立结构，不依赖纯黑死块。
- 不需要把灯光、环境倒影、暖色轮廓光或阴影烘进颜色贴图；这些由 Unity 灯光和 Cubemap 提供。

外形需要原创。不要复制参考产品的 Logo、商标、专属纹样、装饰孔阵列或完整专利轮廓。

## 8. 实时模型与性能预算

这是 iPhone 实时资产，不是离线渲染模型。正式游戏模型要求：

| 项目 | 首选标准 | 硬上限/说明 |
| --- | ---: | --- |
| 组装态可见三角面 | 35,000–45,000 | 不超过 45,000 |
| 拆解态可见三角面 | 45,000–60,000 | 不超过 60,000 |
| 单个 Mesh 顶点 | 优先低于 65,535 | 便于使用 16-bit index |
| Draw Calls | 12–15 | 不超过 15（组装态） |
| 独立材质 | 4–6 | 不超过 6 |
| 运行纹理常驻增量 | 8 MB 内 | 拆解态不超过 10 MB |
| 目标帧率 | 60 FPS | 最终以 iPhone 真机为准 |

可保留高模源文件用于烘焙和宣传渲染，但必须同时交付符合预算的游戏低模。**不接受只有 50 万、100 万或 200 万三角面的模型作为正式 Unity 交付。**

硬表面倒角要有足够几何支撑近景高光，但小划痕、细喷砂和微凹凸优先放进 Normal/Roughness，不要全部堆成几何。复杂视觉 Mesh 与简化 Collision Mesh 分离。

## 9. 拓扑、UV 与 PBR 贴图

- 拓扑干净，无破面、重复面、零面积三角、孤立点或无意的内部重叠面。
- 圆柱、倒角和大面积金属表面法线连续；建议使用合理的硬边、加权法线和与 UV 缝一致的切线空间。
- 所有可见 Mesh 必须有 UV0、Normal 和 Tangent。
- UV 不应无意义地切碎；近景主表面保持一致 texel density，镜像 UV 不得破坏拉丝和文字方向。
- Base Color 不包含灯光、AO、镜面高光或环境色。
- 建议提供：`BaseColor`、`Normal`、`Metallic`、`Roughness`、`AO`；如有透明树脂，再单独说明透明/透射方案。
- 运行贴图以 1024 或 2048 为主；源文件可保留 4K，但不默认进入手机运行包。
- Base Color 使用 sRGB；Normal、Metallic、Roughness、AO 使用 Linear 数据。
- 同时提供 Unity URP 可用的 Metallic-Smoothness 打包图：`R = Metallic`、`A = Smoothness = 1 - Roughness`。
- Normal Map 请注明 OpenGL 或 DirectX 绿色通道约定，不要让 Unity 靠猜测修正。
- 文字、Logo 和装饰若需要换色/解锁，尽量单独材质区、贴花或 mask，不要永久烘死在所有表面。

## 10. 成长装配与后续扩展

旋转类模型后续会有等级成长和装配展示。若首款模型要进入该系统，请尽量预留以下可替换部件：

- 中心材质环或冠环；
- 配重环/配重块；
- 上下辅助轴承或轴套；
- 轴承保持架与轴承球；
- 顶部/底部指帽；
- 可更换树脂件、装饰片或外露金属件。

这些部件主要用于视觉切换和爆炸展示，不改变 Unity 中的质量、惯量或碰撞。每个升级件应能在相同装配基准下直接替换，不能靠手工移动后才能对齐。

## 11. 交付格式

必须交付：

1. `FBX` 游戏模型，Binary 格式，Unity 可直接读取；建议以 FBX 2018/2020 兼容版本导出。
2. 原始 DCC 工程文件，如 `.blend`、`.max`、`.ma/.mb` 之一，保留高模、低模、UV 和烘焙来源。
3. 完整 PBR 贴图源文件与导出图，优先 PNG/TGA，无有损压缩。
4. 材质说明表：材质名称、真实材质意图、Base Color、Metallic/Roughness 范围及贴图对应关系。
5. 零件/层级说明表：哪些固定、哪些旋转、哪些滑动、pivot/轴线、零位、行程、限位和拆解顺序。
6. 正、背、左、右、顶、侧、45° Hero、线框和爆炸视图各一张，用于快速验收比例与结构一致性。
7. 三角面、顶点、Mesh、Renderer、材质和贴图尺寸统计。

可选加分项：

- 一个经过 Unity 6 / URP Lit 导入验证的 Prefab；
- `LOD0 / LOD1` 两级实时模型；
- 机构运动预览视频；
- 可换色 mask 和两套经过验证的材质方案。

`OBJ` 可作为核对几何的附加格式，但不作为主交付，因为它不能完整保留层级、pivot 和材质关系。`STL` 只适合打印检查，也不能代替 Unity 资产。

## 12. 分阶段验收流程

### 阶段 A：概念与结构

- 提供 2–3 个原创轮廓方向；
- 用一张运动示意或爆炸图说明哪里固定、哪里旋转/滑动；
- 确认手掌尺度、拇指接触区、材质组合和核心玩法；
- 在进入高模前确认不会与参考产品构成 1:1 复制。

### 阶段 B：Blockout 运动验证

- 交付低成本灰模 FBX；
- Unity 中验证真实尺寸、轴线、pivot、零位、360° 旋转或完整滑动行程；
- 验证中心固定件不会误跟随转子，所有运动件无穿插；
- 本阶段通过后再做高模、倒角和贴图。

### 阶段 C：高模、低模与材质

- 审核轮廓、倒角、结构层缝和材质分区；
- 提交三角面/材质/贴图统计；
- 在固定 Hero、Top、Side 和微距机位检查高光连续性、法线和纹理闪烁。

### 阶段 D：Unity 最终验收

- FBX 在 Unity Editor `6000.5.6f1` 和 URP 17.5 中无错误导入；
- 根节点归零、尺寸正确、运动件 pivot 正确；
- 组装与拆解状态符合预算；
- Unity 程序可直接控制旋转/滑动与 Reset；
- 自动检查通过后，仍需在真实 iPhone 上检查 60 FPS、内存、温升、镜面闪烁和触感同步。

## 13. 不接受的交付情况

- 全部零件合并为一个不可拆 Mesh；
- pivot 在世界原点、包围盒中心或任意位置，与真实转轴不一致；
- 依赖设计师烘焙的固定时长动画才能运动；
- 非真实比例、负缩放、非统一缩放或层级变换混乱；
- 只有渲染高模，没有可用的游戏低模；
- 固定齿数外露，但无法与 App 的 8/12/24/36 段落配置一致；
- 把环境高光、阴影、暖色轮廓光烘进 Base Color；
- 通过大量材质和 4K/8K 贴图换取离线效果；
- 直接复制第三方品牌、Logo、专利外观或独有纹样；
- 仅在设计师的软件里显示正常，FBX 导入 Unity 后层级、法线、材质或尺寸失效。
