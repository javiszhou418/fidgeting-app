# 磁吸扇牌建模非回归门禁

## 为什么存在

这份门禁用于阻止“修一个新细节，却重新破坏已经确认的旧细节”。背部滑轨过度靠近牌片边缘的问题已经重复出现至少三次；从现在起，它不是主观预览意见，而是带毫米阈值、自动检查和发布阻断的产品约束。

本文件适用于 `magnetic-fan-card` 的 Blender 源模型、FBX、Unity 场景生成器、shipping scene、材质、贴花、相机预览和交互层级。任何新增变量、网格、字体、材质或装配关系都必须保留这里的全部既有约束，除非用户明确要求修改同一条约束。

机器可读副本为：

- `ArtSource/FanCard/fan_card_guardrails.json`
- 校验器：`ArtSource/FanCard/validate_fan_card_guardrails.py`

## 锁定几何

| 项目 | 锁定值 / 规则 |
| --- | --- |
| 单片牌 | `63.5 × 88.9 × 3.5 mm` 刚性实体 |
| 圆角 | 半径 `9.5 mm`，四角圆角；边缘 bevel 约厚度的 `15%` |
| 层间空气 | `1.0 mm`，三层 AABB 不相交 |
| 共同轴心 | 牌片圆角圆心；展示视角位于右下角 |
| 轴孔表面 | 三张暖银面在轴孔外保持完整封闭牌角；轴芯半径 `2.00 mm`、相对外表面下沉 `0.12 mm`，其上只允许一枚 Blender 输出的低矮抛光轴承帽（半径 `2.07 mm`、可见高度 `0.65 mm`）；不得透出场景亮斑、同心悬浮圆环或额外垫圈 |
| 运动层 | 底片固定 `0°`；中片 `45°q`；顶片 `90°q` |
| 稳定档位 | `q = 0 / 1⁄3 / 2⁄3 / 1` |
| 轨道有效弧 | `45°`；Blender 圆头视觉余量不得改变物理弧 |
| 轨道起点 / 随动球 | 相对轴心 `(-43.31, -21.31) mm`；圆角放大后随牌身平移，保持原牌身相对位置与 `7.590 mm` 净距 |
| 暗槽宽度 | `6.2 mm` |
| 金属网宽度 | `4.25 mm` |
| 轨道最小外轮廓净距 | 整条暗槽（含圆头和半宽）到牌片外轮廓始终 `≥ 6.0 mm` |
| 轨道视觉位置 | 位于牌片内部偏左下，不得压住外框或贴近圆角；正面/交互 hero 不得看见轨道 |
| 轨道装配层 | 只允许 `TopCard` 与 `MiddleCard` 的背面有轨道；`BottomCard` 绝不生成轨道。随动件只属于 `MiddleCard` 与 `BottomCard` |
| 磁体 | 每条轨道 3 枚，对应 4 个稳定档位；金属网真实开孔可透出磁体 |
| 正面角标 | 每片正面两个标准扑克牌角标：左上为直立 Oxanium 700 active rank + 同向小黑桃；右下为整组旋转 `180°` 的对角索引。两个 rank、两个黑桃均直属自己的刚性牌片；禁止三枚无语义装饰点 |
| 正面边框 | `1.0 mm` 黑色结构边框；其内为 `0.8 mm` 暖金镶边与 `0.38 mm` 平缓 bevel，再过渡到中珠喷暖银牌面 |
| 背面图案 | 不复制 A、角标黑桃或中央黑桃；背面只展示机械结构 |
| 异常圆件 | 结构轴标记不得带 Renderer；只允许单枚 `CommonAxis_BearingCap_Chrome`，不出现悬浮金属环或多层同心亮弧 |

`6.0 mm` 是失败阈值，不是建议值。当前起点给直线边约 `7.59 mm` 的设计余量，允许 bevel、圆丝和导入法线变化而不重新贴边。

## 唯一坐标规则

不得在 C#、Blender、场景和测试中静默维护互不校验的重复坐标。

1. 先修改 `fan_card_guardrails.json`。
2. 同步 `FanCardSpecifications.cs` 和 Blender 构建脚本。
3. 运行 source-only 校验，任何副本不一致立即停止：

   ```bash
   python3 unity/FidgetingApp/ArtSource/FanCard/validate_fan_card_guardrails.py --source-only
   ```

4. 重新生成 `.blend`、FBX 和 shipping Unity scene。
5. 运行完整校验：

   ```bash
   python3 unity/FidgetingApp/ArtSource/FanCard/validate_fan_card_guardrails.py
   ```

新增变量之前，必须先回答它是否改变以下任一项：外轮廓、轴心、层厚、层距、轨道位置、轨道宽度、角度、父子层级、正背面可见性、Collider 或 Haptic。答案为“是”时，必须在同一修改内更新机器约束与验收测试；不能只让预览“看起来差不多”。

## 强制工作流

1. 修改前读取本文件、`PRODUCT_PLAN.md` 和 `IMPLEMENTATION_STATUS.md`，列出本次不允许退化的既有项。
2. 几何与字体 relief 在 Blender 中制作；Unity 只做导入、材质、装配、交互和 shipping 验收。
3. 改动前后都运行门禁；source-only 先阻止错误坐标进入 FBX，完整门禁再阻止错误场景进入预览。
4. 运行 Unity `CardGeometryValidator`，结果必须为 `=== VALIDATION: ALL PASS ===`。
5. 运行 `FanCardAcceptanceTests`，不得降低通过数或删除旧断言换取通过。
6. 从 shipping Unity scene 生成 top、authored hero、left/right oblique、low-angle、back、轨道特写和本次修改对象特写。
7. 逐项对照，而不是只看新特写：轨道净距、牌片厚度、空气间隙、轴孔、层级运动、正背面图案都必须复核。
8. 任一门禁失败时不得称为“完成”“已集成”或“可以推机”。视觉改动必须先获用户明确批准。

## 预览判定

- 正面、hero 和交互帧：看不到轨道、背面角标、浮环或跨层贴花；三张牌在轴孔处仍保持完整圆角轮廓，孔内不透出场景亮斑。
- 背面：轨道位于左下内部，四周有清楚的金属留边；不能与外框线形成粘连感。
- 低角度：三片均有真实厚度、两道空气间隙，无穿模。
- `0→90°` 交互帧：底片像底座一样不动；中片和顶片分别走一半角度和完整角度；每片的两组 `rank + 黑桃` 只随所属牌片运动，右下组始终保持相对左上组旋转 `180°`。
- 牌面状态只允许整组 `AAA`，或按底片/中片/顶片排列的 `Q/K/A`。每次用户进入详情页以 `50% / 50%` 选择一次整组状态；禁止逐层独立随机、同一张牌两角字母不一致、叠放多个 Renderer，或因换字形改变 Transform、Collider、四档机械、音频与 Haptic。
- 新增材质或网格后仍必须重新检查上述所有旧项目；不能因为本轮只改 A/Q/K、金属网或灯光而跳过滑轨净距。

## 变更记录要求

每次 Fan Card 视觉或建模修改都要在 `IMPLEMENTATION_STATUS.md` 记录：修改内容、明确未变项、门禁和测试证据、shipping 预览路径，以及视觉批准 / 真机验收状态。
